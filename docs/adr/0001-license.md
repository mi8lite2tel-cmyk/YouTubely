# ADR 0001: GPL-3.0-or-later вместо MIT

- Статус: принято
- Дата: 2026-10-12
- Решение принял: владелец репозитория (ответ на вопрос агента)

## Контекст

Репозиторий создан под MIT. Основной бэкенд для получения потоков — NewPipeExtractor
(`com.github.TeamNewPipe:NewPipeExtractor`, v0.26.5) — распространяется под GPL-3.0.
Приложение, которое линкуется с GPL-библиотекой и распространяется в виде APK,
целиком подпадает под условия GPL-3.0. Под MIT такое сочетание распространять нельзя.

Рассматривались варианты:

1. Перейти на `GPL-3.0-or-later` и использовать NewPipeExtractor (так сделано в NewPipe и LibreTube).
2. Остаться на MIT, не линковать NewPipeExtractor и написать собственный клиент Innertube
   или работать через API инстансов Piped/Invidious.

Вариант 2 требует поддерживать собственный экстрактор, который YouTube регулярно ломает.
Кроме того, вариант 2 не делает проект юридически чище: условия YouTube нарушаются
одинаково при любой реализации клиента. Выигрыш сводится к пермиссивной лицензии
кода, и он не стоит этих затрат.

## Решение

- Проект распространяется под **GPL-3.0-or-later**. Файл `LICENSE` содержит канонический
  текст GPL-3.0 с gnu.org (sha256 `3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`).
- Каждый исходный файл (`*.kt`, `*.kts`) начинается с SPDX-заголовка:

  ```kotlin
  // SPDX-FileCopyrightText: 2026 YouTubely contributors
  // SPDX-License-Identifier: GPL-3.0-or-later
  ```

  Наличие заголовка проверяет Spotless (`./gradlew spotlessCheck`), он же выполняется в CI.
- Весь доступ к источникам видео идёт через интерфейс `StreamProvider` (`core/provider`).
  Реализация по умолчанию — `NewPipeStreamProvider`. Бэкенд можно заменить (например, на Piped)
  без переписывания приложения.

## Последствия

- Вклады в проект принимаются под GPL-3.0-or-later.
- Совместимость с F-Droid и IzzyOnDroid сохраняется: обе площадки принимают GPL.
- Зависимости должны быть совместимы с GPL-3.0: Apache-2.0, MIT, BSD, LGPL, OFL для шрифтов.
- **Открытый вопрос — flavor `full`.** Google Cast SDK (`play-services-cast-framework`) проприетарный
  и не является системной библиотекой в смысле GPL. Если распространять APK, в котором он
  слинкован с GPL-кодом NewPipeExtractor, это, скорее всего, нарушит GPL. Добавить исключение
  о линковке мы не можем: права на NewPipeExtractor принадлежат его авторам. До отдельного ADR
  о Cast (это задача P2) flavor `full` технически существует, но Cast в него не добавляется.
  Варианты на будущее: открытая реализация протокола Cast, DLNA/UPnP или отказ от `full`.
- Код, ранее опубликованный под MIT (в репозитории не было ничего, кроме пустого README),
  перелицензирования не требует.
